# `experimental/`

Opt-in scratch space: spikes, throwaway benchmarks of an idea, a module you are
not ready to put under `src/` yet.

```sh
devtools/test.py pr --only cpp --preset experimental     # own build dir, build-experimental/
```

Nothing here is built by a normal configure — the directory is guarded by
`FREE_BREAKFAST_BUILD_EXPERIMENTAL`, which only the `experimental` preset sets.
That is the point: code in here is free to be broken, slow, or half-finished
without costing anyone else a build.

Two things still apply:

- **It is compiled, so it must compile.** A preset nobody runs rots; this one is
  cheap to run, so run it before you leave something in here.
- **ctest entries work.** `enable_testing()` is called before any
  `add_subdirectory` in the root `CMakeLists.txt`, so an `add_test()` here is
  recorded normally. GoogleTest cases go in `test/experimental/`. The root
  `CMakeLists.txt` adds that directory under this same option, and skips it
  under `FREE_BREAKFAST_COMPILE_TIME_ONLY`, which has no GoogleTest. It builds
  its own binary, `free_breakfast_tests_experimental_gpu`.

| [`fp16_gemm/`](fp16_gemm/README.md) | `__half` GEMM through cuBLAS / hipBLAS (`Hgemm`, and `GemmEx` with fp32 accumulation): does each backend support it, how accurately, and how fast against `Sgemm` |

| [`blas_lt/`](blas_lt/README.md) | fp64 GEMM through the cuBLASLt / hipBLASLt heuristic, on the shapes `nevpt2::rdms`' digest runs: does the Lt surface beat plain `Dgemm` there, and does hipBLASLt offer an fp64 algorithm at all |
| [`compress_rdm3/`](compress_rdm3/README.md) | A complete SC-NEVPT2 case with no symmetry, C1 glycolaldehyde DF-CASSCF(10,10), dm3/f3ca/f3ac included: data and its generator for 3-RDM compression experiments; nothing built |

| [`hip_comp/`](hip_comp/README.md) | GPU lossless compression on HIP: hipCOMP's batched LZ4 and Cascaded over device arrays, round-tripped bit-exact on the gfx1200. Cascaded packs sorted int64 indices 8.9× at 71 GB/s compress; LZ4 gets 5.5× on 90%-zero fp64 but compresses at only 1.4–7.5 GB/s; random fp64 stays at 1.00×. HIP only, and only where hipCOMP is installed (not in the image; README has the build) |
| [`routine/`](routine/README.md) | A check-before-invoke CRTP base (`Routine<Self, Alloc>`, one designated-initializer `In`, a shape-only `Shape` for `footprint`) and a compile-time allocation key (`AllocKey`, minted only by a root in the key's module), spiked on a port of `mcscf::root_rotation`. The port matches the original bit for bit on the gfx1200. `footprint(shape)`, built from sizes alone, is the pool's peak exactly. A death test covers `check`'s aborts, and five must-not-compile ctest entries pin the diagnostics. Verdict (#1324): promote the base, `In`, `Shape` and `check`; drop the key, because the one unforgeable friend placement is a module cycle in `src/`'s layering |
| [`library_handle_workspace/`](library_handle_workspace/README.md) | Does a vendor solver or BLAS handle take device memory behind a caller-sized workspace, and what does it do with one too small? cuSOLVER never grows but never checks `lwork`: `syevd` given half writes its full need and reports success (a crash with a tight buffer, silent corruption otherwise). hipSOLVER refuses a short buffer cleanly, and grows device memory mid-run (+34 MiB) or aborts only when given `work = nullptr`. Neither BLAS grows on a call; setting a hipBLAS workspace frees rocBLAS's own 32 MiB pool. RTX 3080 and gfx1200 |
| [`rust/gemm/`](rust/gemm/README.md) | fp64 GEMM driven from Rust over WarpWraps' C ABI (the `wwr-sys` crate), with no C++ of this tree's own: a stream, device buffers and `dgemm` in safe, lifetime-checked types, with a demo checked against a host loop. Cargo is run by hand, not by CMake |
| [`rust/s_overlap/`](rust/s_overlap/README.md) | The spherical AO overlap S of a molecule in a basis, from Rust: a C ABI over the pipeline's setup and overlap steps, copying S into a `rust/gemm` buffer, checked against PySCF to ~1e-15. Also documents that free_breakfast never renormalizes a contraction, so diag(S) is 1 only to the published coefficients' digits (up to 1.3e-6 off in cc-pVTZ) |
| [`rust/rayon_npy/`](rust/rayon_npy/README.md) | One column-major float64 `.npy` written by many rayon threads at once, each `pwrite`-ing its own columns at their fixed offsets; byte-identical to `np.save`. Pure Rust, no GPU, cargo by hand. Threads do not speed up the write itself (it stays ~1.7 GB/s on ext4); they speed up computing the columns |
| [`rust/rayon_npy_mmap/`](rust/rayon_npy_mmap/README.md) | The same file filled in place through a `MAP_SHARED` mapping, each rayon task computing into its own disjoint `&mut [f64]` block of the file's pages. Scales where `pwrite` does not: 3.6 GB/s on 8 threads, 3× its own single thread and 1.9× `rayon_npy`'s best; the per-file page-cache insert is the ceiling |
| [`rust/rayon_npy_direct/`](rust/rayon_npy_direct/README.md) | The same file with `O_DIRECT`: tasks own 4 KiB-aligned stripes of the *file* (flat element ranges, header in stripe 0), filled into page-aligned buffers; preallocated and pre-extended so no write allocates or extends. Device-bound on this box's shared SSD (~0.08 GB/s, `dd`'s rate); through `fdatasync` all three writers tie there |
| [`rust/df_metric/`](rust/df_metric/README.md) | The density-fitting Coulomb metric (P\|Q) computed on the host in plain Rust, as its packed lower triangle over the spherical functions: one-function-per-electron McMurchie-Davidson over the rebuild's device-free basis crates, each shell block formed directly in the solid harmonics (Hobson's theorem: the top-order Hermite Gaussians alone, no Cartesian integral), and far pairs of shells from one block per pair of atoms and momenta (the derivatives of 1/R, the exponents left in a per-shell scalar). The Boys function is the C++ tree's `eval_boys`, ported. Matches PySCF's `int2c2e` to 1.3e-14 on water in cc-pVDZ-JKFIT, 1.6e-14 through i shells and 2.4e-14 on gly10 (3606 functions). One rayon task per atom: 0.14 ms for water on one thread; gly100 (35,016 functions, a 4.6 GiB triangle) in 3.3 s on one thread and 0.47 s on eight, against 28 s and 3.7 s for the route through Cartesian integrals kept beside it. Needs the FMA target feature, which its `.cargo/config.toml` sets. No GPU, cargo by hand |
| [`rust/s_overlap_host/`](rust/s_overlap_host/README.md) | `rust/s_overlap`'s S computed on the host in plain Rust, built like `rust/df_metric`: each shell block directly in the solid harmonics by Hobson's theorem, where a Gaussian's derivatives factor over the axes, so there is no Boys function and no Hermite table, only three 1-D recurrences per primitive pair; primitive pairs past `mu R² >= 40 + 4L` skipped, and shell pairs past it left zero. Matches PySCF on `rust/s_overlap`'s fixtures to 8.9e-16, through f. gly10 in cc-pVTZ (1678 AOs) takes 20 ms on one thread and 2.4 ms on 24, against 52 ms on 24 for the Obara-Saika route through Cartesian integrals kept beside it. Needs the FMA target feature, which its `.cargo/config.toml` sets. No GPU, cargo by hand |
| [`rust/t_kinetic_host/`](rust/t_kinetic_host/README.md) | The AO kinetic energy T computed on the host in plain Rust, beside `rust/s_overlap_host`: T is `-∇²/2` of S in the pair separation, so each shell block is S's Hobson-theorem block with the same three 1-D recurrences run two orders further, and no Cartesian integral; primitive pairs past `mu R² >= 40 + 4(L + 2)` skipped, and shell pairs past it left zero. Matches PySCF's `int1e_kin` on the rebuild's kinetic fixtures to 3.7e-16, through f. gly10 in cc-pVTZ (1678 AOs) takes 28 ms on one thread and 3.0 ms on 24, against 99 ms on 24 for the Obara-Saika route through Cartesian integrals kept beside it. `overlap_and_kinetic` returns S and T from one pass over the same exponentials and recurrences, at 1.26-1.31x T alone against about 1.75x for the two run one after the other (36 ms against 49 ms on one thread); its S matches PySCF to 1.0e-15 and its T is `kinetic`'s bit for bit. Needs the FMA target feature, which its `.cargo/config.toml` sets. No GPU, cargo by hand |
| [`rust/v_potential_en_host/`](rust/v_potential_en_host/README.md) | The nuclear attraction V of `rust/integrals/one_electron/potential_en` computed on the host in plain Rust, packed lower triangle like `rust/s_overlap_host`: McMurchie-Davidson with every nucleus summed into one Hermite table, built once per distinct primitive pair of a pair of atoms (the generally contracted cc sets repeat exponents across shells, so only 12-20% of primitive pairs are distinct), far nuclei seeded in closed form with no Boys function, then a sparse spherical transform; pairs past the overlap's cutoff, raised by `ln(sum Z 2pi/p c_a c_b)`, left zero. The Boys function is `rust/df_metric`'s. Matches PySCF's `int1e_nuc` on the device crate's fixtures to 5.7e-15, through f. gly10 in cc-pVTZ takes 0.60 s on one thread and 52 ms on 24, against 25 s and 1.8 s for the Obara-Saika + HRR route kept beside it. Needs the FMA target feature, which its `.cargo/config.toml` sets. No GPU, cargo by hand |
| [`rust/v0.0.2/`](rust/v0.0.2/README.md) | A prototype of the Rust rebuild's redesign: steps over one MainBus, a `mem_budget` per step that counts and allocates (no planner, no arena), and one step DAG run in two modes on rustflow. DF-RHF on one card through it matches the old Rust path to 1e-13 hartree on water, benzene and ethylene, iteration for iteration on the first two. Its README lists what held and thirteen things the prototype says to change. A workspace of its own, cargo by hand, after `rust/`'s CMake project is built |
| [`dag_transitive_closure/`](dag_transitive_closure/README.md) | Step scratch packed from the transitive closure of the step DAG, as the Rust redesign proposes: two regions overlap only when the DAG orders their steps. | [`cope_rearrangement/`](cope_rearrangement/README.md) | A study of the chair Cope rearrangement of 1,5-hexadiene (CASSCF(6,6) vs NEVPT2). Steps 1 and 2 are PySCF/block2 references: done, and partial. Step 4 runs on free-breakfast's own DF-PC-NEVPT2: 4a, its energies against block2's at all 23 scan points, is done (4e-10 on the same orbitals and CI); 4b is done: PC-NEVPT2's one C2h stationary point (R = 1.922 Å) has a single a_u imaginary frequency and descends both ways to 1,5-hexadiene (barrier 31.2 kcal/mol), while CASSCF has a diyl minimum and an a_u saddle. Nothing built |
