# Dipole gradient

The dipole integrals' nuclear derivative contracted with an AO matrix on the
GPU, over the `gmu_{la}{lb}` kernels FelizJueves generates
(`gradient/kernel_gmu.py`, its `Target.DIPOLE` at derivative order 1):

    G[c, A, k] = Σ_mn M_mn dμ^c_mn/dR_{A,k},   μ^c_mn = <m| r_c |n>

per component c = x, y, z, atom A and axis k, for a spherical AO matrix M, μ
about the origin as `dipole/` builds it, the derivative integrals never
formed. An RHF dipole derivative's explicit term is −G at M = D, the
electrons carrying charge −1 (`hessian::rhf_dipole_derivative`).

## Module

`free_breakfast.integrals.one_electron.dipole_gradient`, also re-exported by
`free_breakfast.integrals.one_electron` and `free_breakfast.integrals`.

## Design

`gradient/`'s contraction, one family: the call checks its inputs, carries M
onto the Cartesian layout (`MatrixAOPair::spherical_to_cartesian`), builds
each Cartesian AO's atom from the basis's per-atom shell map, and launches one
generated kernel per `mmd` class, one thread per record, each class on its own
stream (`launch_each`), into one zeroed `[3, n_atom, 3]` device gradient,
which it downloads after waiting for `res.stream()`. Before each class's
kernel a small gather kernel (`dipole_gradient_launch.cu`) writes the class's
record atoms from its AO offsets, as `gradient/`'s does.

**The origin is fixed, not a nucleus.** The kernels take the origin C and a
charge q at run time; the launcher passes C = 0 and q = 1, `dipole/`'s. Only
the basis functions move, so there is no operator term, and both centres of
every pair are differentiated. Moving every atom by t is moving the origin by
−t, so Σ_A G[c, A, k] = δ_ck Σ_mn M_mn S_mn: a check, not a construction.

**The weight.** Per shell pair the kernels weight Cartesian pair (r, c) by
`M[a_r, b_c] + M[b_c, a_r]` off the diagonal and `M[a_r, a_c]` on it, as
`gradient/`'s, so M need not be symmetric.

**The kernels.** `kernels/gmu_{00,01,02,03,11,12,13,22,23,33}.cu` (every
`la <= lb <= 3`), the dipole half of FelizJueves's `--grad-mu-l 3` ladder
(its `gquad_` quadrupole units are not emitted), generated by
`tools/emit/dipole_gradient_kernels.py` and committed as emitted, each one
explicit specialization of `dipole_gradient<la, lb>`; the launcher includes
only `kernels/dipole_gradient.h` and launches through its table, bounded by
its extent. They reach f, past `dipole/`'s d: the moment kernels at d1 are
validated against libcint's `int1e_irp` through (ff) in FelizJueves.

**Limits.** f per shell (`launch`'s `kOneElectronMaxL`), `n_ao² ≤ INT32_MAX`
over Cartesian AOs, and every input on the call's device; each is
`InvalidConfig` before anything is launched. The classes must be
`primitive_pair_classes` of the basis given.

## Public API

| Symbol | Role |
|---|---|
| `dipole_gradient(res, basis, classes, m)` | `Result<std::vector<double>>`: Σ M dμ^c/dR, `(3, natoms, 3)` row-major, G[c, A, k] at `3 (natoms c + A) + k` |

## Usage

```cpp
import free_breakfast.integrals;
namespace fb = free_breakfast;

const auto classes = fb::primitive_pair_classes(res, *basis);   // once per basis
fb::SphericalMatrixAO d(res, *basis);                             // the density
const auto g = fb::dipole_gradient(res, *basis, *classes, d);   // -g: the electrons'
```

## Tests

`test/gtest/dipole_gradient_gpu.cpp` (suite `DipoleGradientGolden`): the skew
water in cc-pVDZ and cc-pVTZ (every class through (ff)) against libcint's
`int1e_irp` contracted with the recipe matrix 1 / (m + n + 1) by PySCF
(`test/gtest/data/dipole_derivative/`,
`tools/emit/dipole_derivative_reference.py`, which checks it against central
differences of `int1e_r`), at 1e-10 of max |G|, and the sum rule above at
1e-12 of max |G|; plus (`DipoleGradient`) the refusals of a matrix of the
wrong order and a basis with no per-atom map. These are the kernels' first
run on a card: FelizJueves compiles them but has no device harness. Measured
on the RTX 3080 (CUDA): 2.2e-16 (cc-pVDZ) and 1.9e-15 (cc-pVTZ) of max |G|
from libcint, the sum rule to 2.1e-15 and 1.7e-14.
