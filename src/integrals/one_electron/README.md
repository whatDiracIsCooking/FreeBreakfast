# One-electron

One-electron integral matrices on the GPU, over kernels FelizJueves generates:
the overlap S, the kinetic energy T, the nuclear attraction V, and the core
Hamiltonian H = T + V.

## Module

`free_breakfast.integrals.one_electron`, also re-exported by
`free_breakfast.integrals`.

## Design

`upload_primitive_pairs` copies `mmd`'s records to the device once per basis,
and `upload_nuclei` a molecule's nuclei (Z and position) once per geometry. A
build then zeroes a `CartesianMatrixAO` and launches one generated kernel per
class, one thread per record: `s_{la}{lb}` for S, `t_{la}{lb}` for T,
`v_{la}{lb}` for V (the nuclei serial inside each record). Each thread adds its
values at `(m, n)` and `(n, m)` with fp64 atomics, so a matrix is symmetric to
rounding (the two mirror positions are summed in different orders), not
bitwise. The spherical matrix is `MatrixAOPair::cartesian_to_spherical` of the
result.

**H is built in place.** `core_hamiltonian` zeroes H once and launches the T
and then the V kernels of every class into it. Both only add, so T + V is formed
without a T or V matrix of its own and without a separate addition.

**One record set serves all three.** S reads `zeta`, `xpa`, `xpb`, `s` and the
offsets; T reads those and `eb`, the ket exponent; V reads those and `p`, the
product centre. `mmd` builds them all, whichever matrix is wanted.

**The kernels.** `s_overlap/`, `t_kinetic/` and `v_nuclear/`, each
`{00,01,02,11,12,22}.cu` (every `la <= lb <= 2`), generated by
`tools/emit_one_electron_kernels.py` and committed as emitted. They are
FelizJueves's CUDA spelling plus wwr's `#include <runtime.h>`, which makes the
same text compile under clang `-x hip`. Each family's launcher
(`overlap_launch.cu`, `kinetic_launch.cu`, `nuclear_launch.cu`) `#include`s
them rather than compiling them as sources of their own, so it launches kernels
whose definitions it can see; listing them as sources too would define each
`extern "C"` kernel twice.

**V's kernels each carry their own Boys function.** Every `v_*.cu` defines the
same non-static `__device__ double fj_boys(int, double)` (FelizJueves's wide
one: the Kummer series below T = 125, the asymptote above, because a point
charge has no exponent to damp `T = ζ|P − C|²`). Six of them in one TU would
define it six times, so `nuclear_launch.cu` includes each inside a namespace
of its own (`device::nuclear_{la}{lb}`). The emitted text is untouched.

**Limits.**

- d per shell (`device::kOneElectronMaxAngularMomentum`); a class above is
  `InvalidConfig`, before anything is launched.
- The kernels index the matrix as a 32-bit `m * n_ao + n`, so
  `n_ao² ≤ INT32_MAX` (about 46k Cartesian AOs); above is `InvalidConfig`.
- The records' AO offsets are not checked against the matrix's order: the
  classes must come from the basis the matrix was made for.
- V is one thread per record with every nucleus serial inside it, and its
  kernels spill registers from `la + lb = 3` (FelizJueves's
  `docs/implementation/one_electron.md`). A warp per record is FelizJueves's
  named follow-up.

## Public API

| Symbol | Role |
|---|---|
| `DevicePrimitivePairClass` | One class's records on the device, the same fields as `PrimitivePairClass` |
| `upload_primitive_pairs(res, classes)` | `Result<std::vector<DevicePrimitivePairClass>>`. Synchronizes once, so the host classes may be released on return |
| `DeviceNuclei` | A molecule's nuclei on the device: `z`, `c` (bohr), `n_nuc`, and the `dev_idx` they are on |
| `upload_nuclei(res, molecule)` | `Result<DeviceNuclei>`, in atom order. `InvalidConfig` for a molecule with no atoms. Synchronizes once |
| `overlap(res, classes, s)` | `Status`: the Cartesian S into `s` |
| `kinetic(res, classes, t)` | `Status`: the Cartesian T into `t` |
| `nuclear_attraction(res, classes, nuclei, v)` | `Status`: the Cartesian V into `v`, point nuclei |
| `core_hamiltonian(res, classes, nuclei, h)` | `Status`: the Cartesian H = T + V into `h` |

Every build is queued on `res.stream()`, with no host synchronization.

## Usage

```cpp
import free_breakfast.integrals;
import free_breakfast.linalg.matrix_ao;
namespace fb = free_breakfast;

const auto classes = fb::primitive_pair_classes(basis);       // host
const auto device = fb::upload_primitive_pairs(res, *classes); // once per basis
const auto nuclei = fb::upload_nuclei(res, molecule);          // once per geometry
fb::CartesianMatrixAO s(res, basis);
fb::CartesianMatrixAO h(res, basis);
fb::Status status = fb::overlap(res, *device, s);
status = fb::core_hamiltonian(res, *device, *nuclei, h);
```

## Tests

- `test/gtest/overlap_gpu.cpp`: H₂O in STO-3G and cc-pVDZ against libcint's
  `int1e_ovlp` at 1e-12 · max|S|, plus the zeroing and the class-range refusal.
- `test/gtest/core_hamiltonian_gpu.cpp`: the same two molecules' T, V and H
  against libcint's `int1e_kin` and `int1e_nuc` and PySCF's `hcore`, at the
  same tolerance, plus each build's zeroing and class-range refusal, and
  `upload_nuclei`'s refusal of an empty molecule.
