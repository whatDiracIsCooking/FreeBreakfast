# Overlap, mixed

The Cartesian overlap S_{rows,cols} between two bases on the GPU, over the
`overlap_mixed<la, lb>` kernels FelizJueves generates (its `Target.SX`).

## Module

`free_breakfast.integrals.one_electron.overlap_mixed`, also re-exported by
`free_breakfast.integrals.one_electron` and `free_breakfast.integrals`.

## Design

**One routine for four cases.** `S[m, n] = <m|n>`, m an AO of `rows` and n of
`cols`. A basis carries its geometry (each shell's centre), so the two bases
may differ in basis set, in geometry, in both, or in neither, and nothing here
tells those apart. A basis against itself is the square S `overlap/` builds;
this directory is its sibling for now, so that one keeps its consumers while
this one proves itself.

**The records are the call's own.** `overlap_mixed` checks its inputs, builds
`mmd`'s `mixed_primitive_pair_classes(rows, cols)` (every ordered shell pair
(i of `rows`, j of `cols`), never swapped, so 9 classes through d where a
basis has 6), zeroes `s` on `res.stream()` and launches one generated kernel
per class on that class's stream (`launch`'s `launch_each`), one thread per
record. Each thread adds its values once, with fp64 atomics: no mirror, no
diagonal rule, every element owned by exactly one ordered shell pair. So a
basis against itself comes out symmetric to rounding, not bitwise, as
`overlap/`'s S does.

**The output is a plain `Buffers::device<double>`**, column-major
`rows.nao_cart() x cols.nao_cart()` with leading dimension `rows.nao_cart()`:
`MatrixAO`'s layout, so it goes straight into a BLAS call. There is no matrix
type for a rectangular AO matrix yet, so the buffer's device cannot be checked
(a wwr buffer does not expose its handle): it must be `res.device()`'s.

**The kernels write row-major, so the launcher swaps the class.** FelizJueves's
kernel writes `S[(off_a + i) * n_b + (off_b + j)]`, row-major in its row
basis. `overlap_mixed_class` launches `overlap_mixed<lb, la>` with `P - A` and
`P - B`, `off_a` and `off_b`, and the two AO counts exchanged: the columns'
shell becomes the kernel's row, and since `<n|m> = <m|n>`, its row-major
`n_cols x n_rows` is the column-major `n_rows x n_cols` the API promises. No
FelizJueves change, and every ordered class is emitted, so the swapped class
always has a kernel.

**The kernels.** `kernels/sx_{la}{lb}.cu`, every ordered `(la, lb)` through
d, generated by `tools/emit_one_electron_kernels.py` (its `ORDERED_FAMILIES`)
and committed as emitted. `kernels/overlap_mixed.h` declares the template,
each specialization, and `overlap_mixed_kernels`, the full `[la][lb]` table.

**Limits.** d per shell (`kMaxAngularMomentum`), and
`rows.nao_cart() * cols.nao_cart() <= INT32_MAX`; either is `InvalidConfig`
before anything is formed or launched, as is a buffer of the wrong size.

**The spherical form** is `overlap_mixed_spherical`: the Cartesian block
carried over as `U_rowsᵀ S_cart U_cols`, each U the basis's
`spherical_transform_matrix` uploaded, two gemms. Column-major
`rows.nao_sphe() x cols.nao_sphe()`, the layout `SphericalMatrixAO` uses, into
a plain buffer for the same reason as above. It synchronizes the stream once,
at the end, so the host U's outlive their upload. `localization/ibo` uses it;
`pipeline/casci`'s AVAS still applies its U's itself, on the host, over only
the labelled AOs.

## Public API

| Symbol | Role |
|---|---|
| `overlap_mixed(res, rows, cols, s)` | `Status`: the Cartesian S_{rows,cols} into `s` |
| `overlap_mixed_spherical(res, rows, cols, s)` | `Status`: the spherical S_{rows,cols} into `s` |

## Usage

```cpp
import free_breakfast.core.wwr;
import free_breakfast.integrals.one_electron.overlap_mixed;
namespace fb = free_breakfast;

fb::Buffers::device<double> s(std::size_t{rows.nao_cart()} * cols.nao_cart(), res.device());
fb::Status status = fb::overlap_mixed(res, rows, cols, s);  // s(m, n) at m + n * rows.nao_cart()
```

## Tests

`test/gtest/overlap_mixed_gpu.cpp`, one case per cell of {same, different}
basis set x {same, different} geometry: a basis against itself against
libcint's `int1e_ovlp` and against `overlap`; H₂O STO-3G against 6-31G and
cc-pVDZ, and against 6-31G at another geometry, against libcint's
`intor_cross` (`test/gtest/data/overlap_mixed/`), both orientations; s and p
shells against themselves translated, against the closed form. The spherical
form on the cross fixtures, against libcint's values carried over on the host
by each basis's U (cc-pVDZ's d shells make the transform not an identity).
Every build writes into a buffer of NaN. Plus the refusals.
