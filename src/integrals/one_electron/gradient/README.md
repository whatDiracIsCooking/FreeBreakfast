# Gradient (one-electron)

The one-electron nuclear-gradient contractions on the GPU, over the `gs_`,
`gt_` and `gv_{la}{lb}` kernels FelizJueves generates: for the overlap S, the
kinetic energy T and the nuclear attraction V,

    G[A, k] = Σ_mn M_mn dX_mn/dR_{A,k}

per atom A and axis k, for a spherical AO matrix M, with the derivative
integrals never formed. The signs and halves of an energy are the caller's, as
in FelizJueves (`docs/implementation/gradient.md`): an RHF gradient takes M = D
for T and V, and M = −W, the energy-weighted density negated, for S.

Beside them, the derivative integrals themselves, which a Hessian's CPHF
right-hand sides need as matrices (`.temp/hessian/rhf_hessian.tex` §6, "The
one-electron part"): S^x, T^x and V^x, dX_mn/dR_{A,k} for every atom and axis,
as the `[n_atom, 3, n_ao, n_ao]` spherical tensor on the device
(`overlap_derivative`, `kinetic_derivative`, `potential_derivative`), over
FelizJueves's `ips_`, `ipt_`, `ipv_` and `iprv_{la}{lb}` kernels.

And one half: `overlap_half_gradient`, the overlap's derivative on the first
index's centre alone, contracted per atom,

    G[A, k] = Σ_{m on A} Σ_n A_mn ∂S_mn/∂A_k   (only m's centre moved)

which, unlike `overlap_gradient`, does not vanish for an antisymmetric A: the
CSF term of a state-averaged CASSCF nonadiabatic coupling,
½ Σ_mn A_mn ⟨∂m|n⟩ with A = C_a (γ^IJ − γ^IJᵀ) C_aᵀ.

## Module

`free_breakfast.integrals.one_electron.gradient`, also re-exported by
`free_breakfast.integrals.one_electron` and `free_breakfast.integrals`.

## Design

Each function checks its inputs, carries M onto the Cartesian layout
(`MatrixAOPair::spherical_to_cartesian`, U M Uᵀ, as the Fock build carries the
density), and launches one generated kernel per `mmd` class, one thread per
record, each class on its own stream (`launch_each`), into one zeroed
`[n_atom, 3]` device gradient, which it downloads. It waits for `res.stream()`
to do so: the gradient is returned on the host, flat and row-major, as
`molecule`'s `nuclear_repulsion_gradient` is.

**The atoms.** The kernels read each record's two atoms, `atom_a` and
`atom_b`, which `mmd`'s records do not carry. The call builds each Cartesian
AO's atom from the basis's per-atom shell map (`BasisSet::atom_shell_offset`,
set by `place`), uploads that O(AO) table, and before each class's kernel a
small gather kernel (`gradient_launch.cu`) writes the class's record atoms
from its AO offsets into the call's own scratch. A basis with no per-atom map
is `InvalidConfig`. For V the atoms are the nuclei, so the molecule must be the
one the basis was placed on (its atom count is checked).

**The weight.** Per shell pair the kernels weight Cartesian pair (r, c) by
`M[a_r, b_c] + M[b_c, a_r]` off the diagonal and `M[a_r, a_c]` on it, which
is Σ_mn M_mn X_mn exactly for any M, symmetric or not, and either layout.

**No translational invariance is used.** Both centres of a pair, and for V
every nucleus (the Hellmann–Feynman term), are differentiated, so
Σ_A G[A] = 0 is a check rather than a construction.

**The kernels.** `kernels/{gs,gt,gv,ips,ipt,ipv,iprv}_{00,01,02,03,11,12,13,22,23,33}.cu`
(every `la <= lb <= 3`), FelizJueves's `--grad-l 3` ladder less its `gjab_`
units (the Coulomb gradient's), generated by
`tools/emit/one_electron_gradient_kernels.py` and committed as emitted, each
one explicit specialization of its family's kernel template
(`overlap_gradient`, `kinetic_gradient`, `potential_gradient`), compiled as a
source of the one device library; `gradient_launch.cu` includes only
`kernels/<family>.h` and launches through each `<family>_kernels` table,
bounded by its extent. `gv` is low-stack from `la + lb = 5` ((df), (ff)),
FelizJueves's own choice (`kernel_g1e.g1e_lowstack`); its units include the
shared `eval_boys.h`. The derivative-matrix units are FelizJueves's
`--ip-one-e-l 3` ladder (`hessian/kernel_ip1e.py`), templates `overlap_ip1`,
`kinetic_ip1`, `potential_ip1` and `potential_rinv`; `ipv` and `iprv` are
always the rolled form and include `eval_boys.h` too.

**The derivative matrices.** FelizJueves's ip1 kernels write the first-index
derivative X1[k, m, n] = dX_mn/dA_k, A the centre of m, for all atoms in one
launch per class, into a zeroed Cartesian `[3, n_cart, n_cart]`; each slab is
carried onto the spherical layout (`MatrixAOPair::cartesian_to_spherical`, U
being block-diagonal by shell, so a spherical row keeps its atom) into a
`[3, n, n]` Y. Atom A's matrix is then Y's rows on A plus their transpose,
`out[A, k, m, n] += [atom(m) = A] Y[k, m, n] + [atom(n) = A] Y[k, n, m]`, one
hand-written kernel (`gradient_launch.cu`'s `centre_derivatives`) over every
spherical AO's atom. For V the ip1 kernel holds every nucleus's operator
fixed; the operator's own derivative, dV^C/dC_k with V^C = −Z_C/|r − C|, is
`iprv_`, one launch per class and nucleus C into the same Cartesian scratch,
carried onto the spherical layout as atom C's three slabs before the centre
terms are added. Translational invariance is not used, so Σ_A X^(A,k) = 0 is a
check. Each matrix is symmetric to rounding, so either layout reads the result.
The kernels index all three slabs as one 32-bit index, so `3 n_cart² ≤
INT32_MAX`, and the assembly launches one grid row per matrix, so `3 n_atom ≤
65535`.

**The half gradient.** `overlap_half_gradient` builds the overlap's Y exactly
as `overlap_derivative` does (the `ips_` launches into the Cartesian
`[3, n_cart, n_cart]`, each slab carried onto the spherical `[3, n, n]`), but
assembles no matrices: one hand-written kernel (`first_index_row_sums`, one
`kFourWarps` block per AO row m and axis k, `block_reduce` over the columns)
writes rows[k, m] = Σ_n A_mn Y[k, m, n], and the host adds each row into its
atom's, in AO order, so the result is deterministic. *The index convention*:
Y[k, m, n] = ∂S_mn/∂A_k with A the centre of m alone, which is −(∂_k m | n) =
(m | ∂_k n) with ∂_k the electron coordinate's: libcint's `−int1e_ipovlp`,
PySCF's `pyscf.grad.rhf.get_ovlp`, whose nabla is on the first (bra) index —
the comment in `pyscf.nac.sacasscf._nac_csf` that it differentiates the
second index means the electron derivative on the ket, the same number by
parts. So G is twice `_nac_csf`'s per-atom sum for the same A (that function's
½ is the caller's), and for a symmetric A, 2 G is `overlap_gradient`'s. A is
read as row m, column n of the (column-major) spherical matrix; it need not be
symmetric. Its limits are `overlap_derivative`'s but the atom count's, which
nothing here grids over.

**The family layout** is `overlap/`'s, three families to one directory; the
parent README's "One layout per kernel family" has the table.

**Limits.** f per shell (`launch`'s `kOneElectronMaxL`), `n_ao² ≤ INT32_MAX`
over Cartesian AOs, and every input on the call's device; each is
`InvalidConfig` before anything is launched. The classes must be
`primitive_pair_classes` of the basis given: their AO offsets are not checked
against it.

## Public API

| Symbol | Role |
|---|---|
| `overlap_gradient(res, basis, classes, m)` | `Result<std::vector<double>>`: Σ M dS/dR, `(natoms, 3)` row-major |
| `kinetic_gradient(res, basis, classes, m)` | The same for T |
| `potential_gradient(res, basis, classes, molecule, m)` | The same for V, its operator term on every nucleus included |
| `overlap_half_gradient(res, basis, classes, a)` | `Result<std::vector<double>>`: Σ_{m on A} Σ_n a_mn ∂S_mn/∂A_k, the first index's centre only, `(natoms, 3)` row-major; any `a`, antisymmetric included |
| `overlap_derivative(res, basis, classes)` | `Result<Buffers::device<double>>`: S^x, dS_mn/dR_{A,k}, `natoms × 3` spherical matrices, matrix 3A + k at `(3A + k) n²` |
| `kinetic_derivative(res, basis, classes)` | The same for T |
| `potential_derivative(res, basis, classes, molecule)` | The same for V, its operator term on every nucleus included |

## Usage

```cpp
import free_breakfast.integrals;
import free_breakfast.recipes.matrix_ao;
namespace fb = free_breakfast;

const auto basis = fb::place(stamp.primitive_normalized(), molecule);
const auto classes = fb::primitive_pair_classes(res, *basis);   // once per basis
fb::SphericalMatrixAO d(res, *basis);                             // the density
const auto g_t = fb::kinetic_gradient(res, *basis, *classes, d);
const auto g_v = fb::potential_gradient(res, *basis, *classes, molecule, d);
```

## Tests

`test/gtest/one_electron_gradient_gpu.cpp`: the skew water in cc-pVDZ and
cc-pVTZ (every class through (ff)) against libcint's `int1e_ipovlp`,
`int1e_ipkin` and `int1e_ipnuc` + `int1e_iprinv`, contracted with
`test/gtest/data/gradient/`'s recipe matrix by PySCF, at 1e-10 of max|G|, and
each gradient's sum over atoms below 1e-10; plus the refusals of a matrix of
the wrong order, a basis with no per-atom map and a molecule of another atom
count.

`test/gtest/one_electron_derivative_gpu.cpp`: the same two waters' S^x, T^x
and V^x, every element against libcint's `int1e_ipovlp`, `int1e_ipkin` and
`int1e_ipnuc` + `int1e_iprinv`, assembled as PySCF's hcore generator does
(`test/gtest/data/one_electron_derivative/`,
`tools/emit/one_electron_derivative_reference.py`), at 1e-12 of max|X^x|; each
set's sum over atoms below the same; each matrix contracted with the recipe M
against `overlap_gradient` and its siblings at 1e-12 of max|G|; and the
refusals of a basis with no per-atom map and a molecule of another atom count.

`test/gtest/overlap_half_gradient_gpu.cpp`: `overlap_half_gradient` of the
same two waters for a symmetric, an antisymmetric and a general recipe A
against libcint's `−int1e_ipovlp` contracted per atom by PySCF, twice
`_nac_csf` (`test/gtest/data/overlap_half_gradient/`,
`tools/emit/overlap_half_gradient_reference.py`, which also checks a finite
difference moving the bra's centre alone), at 1e-12 of max|G|; for the
symmetric A, 2 G against `overlap_gradient` at 1e-12 of max|G|; and the
refusals of a matrix of the wrong order and a basis with no per-atom map.
