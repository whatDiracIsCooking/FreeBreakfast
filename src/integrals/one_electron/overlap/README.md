# Overlap

The Cartesian overlap matrix S on the GPU, over the `overlap<la, lb>` kernels
FelizJueves generates.

## Module

`free_breakfast.integrals.one_electron.overlap`, also re-exported by
`free_breakfast.integrals.one_electron` and `free_breakfast.integrals`.

## Design

`overlap` runs `check_one_electron_build` (`upload`), zeroes the
`CartesianMatrixAO`, and launches one generated kernel per class, one thread per
record. Each thread adds its values at `(m, n)` and `(n, m)` with fp64 atomics,
so S is symmetric to rounding (the two mirror positions are summed in different
orders), not bitwise. Queued on `res.stream()`, each class on its own stream,
forked from it and joined back into it (`DevicePrimitivePairs::launch_each`),
with no host synchronization.

**The kernels.** `kernels/s_{00,01,02,11,12,22}.cu` (every `la <= lb <= 2`),
generated by `tools/emit_one_electron_kernels.py` and committed as emitted.
They sit in `kernels/` so that directory's `.clang-format`, which turns
formatting off, reaches them and not the hand-written code here.
Each is one explicit specialization of the kernel template `overlap`, compiled
as a source of the device library. `overlap_launch.cu` includes only
`kernels/overlap.h`, which declares the template and every specialization and
holds `overlap_kernels`, the `[la][lb]` table it launches through.

**The family layout.** `kinetic/` and `potential_en/` are the same files under
their own names; the parent README's "One layout per kernel family" has the
table. The launcher takes `upload`'s `PrimitivePairClassView`, not loose
pointers, and is bounded by `basis`'s `kMaxAngularMomentum`, the one limit for
every family.

**Limits.** d per shell (`kMaxAngularMomentum`), and `n_ao² ≤ INT32_MAX`;
either is `InvalidConfig` before anything is launched. The records' AO offsets
are not checked against the matrix's order: the classes must come from the
basis the matrix was made for.

## Public API

| Symbol | Role |
|---|---|
| `overlap(res, pairs, s)` | `Status`: the Cartesian S into `s` |

## Usage

```cpp
import free_breakfast.integrals.one_electron.upload;
import free_breakfast.integrals.one_electron.overlap;
import free_breakfast.linalg.matrix_ao;
namespace fb = free_breakfast;

const auto device = fb::upload_primitive_pairs(res, basis);  // once per basis
fb::CartesianMatrixAO s(res, basis);
fb::Status status = fb::overlap(res, *device, s);
```

## Tests

`test/gtest/overlap_gpu.cpp`: H₂O in STO-3G and cc-pVDZ against libcint's
`int1e_ovlp` at 1e-12 · max|S|, plus the zeroing and the class-range refusal.
