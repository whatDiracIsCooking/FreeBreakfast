# Integrals

Gaussian integrals over a `BasisSet`, on the GPU, with kernels generated by
[FelizJueves](../../deps/FelizJueves) (a submodule at `deps/FelizJueves`).

## Module

`free_breakfast.integrals`, which re-exports the three below.

```
mmd/           free_breakfast.integrals.mmd: host-side McMurchie-Davidson primitive-pair records
one_electron/  free_breakfast.integrals.one_electron: the one-electron matrices S, T, V and H = T + V on the GPU
  launch/            free_breakfast.integrals.one_electron.launch: the per-class launch and the pre-launch checks
  overlap/           free_breakfast.integrals.one_electron.overlap: the overlap S
  kinetic/           free_breakfast.integrals.one_electron.kinetic: the kinetic energy T
  potential_en/      free_breakfast.integrals.one_electron.potential_en: the electron-nuclear potential V
  core_hamiltonian/  free_breakfast.integrals.one_electron.core_hamiltonian: H = T + V
coulomb/       free_breakfast.integrals.coulomb: the Coulomb matrix J of an AO density on the GPU, unscreened
```

## How the pieces fit

```
BasisSet --primitive_pair_classes--> PrimitivePairClass[]          (mmd, on the device, once per basis)
         --overlap / kinetic-->      CartesianMatrixAO S, T        (one launch per class, each on its own stream)
Molecule(res, atoms)                  nuclei on the device          (molecule, once per geometry)
         --nuclear_attraction-->     CartesianMatrixAO V           (one launch per class)
         --core_hamiltonian-->       CartesianMatrixAO H = T + V   (two launches per class, one matrix)
CartesianMatrixAO D                   an AO density
         --coulomb-->                CartesianMatrixAO J           (dq per class, then e_hermite per class pair and jab per class)
         --MatrixAOPair::cartesian_to_spherical-->  spherical      (linalg.matrix_ao)
```

**Generated kernels are committed, not built.** `tools/emit_one_electron_kernels.py`
and `tools/emit_coulomb_kernels.py` write them from the FelizJueves submodule; a
build never runs Python. Re-run both after bumping the submodule. Each family
has its own directory (`one_electron/{overlap,kinetic,potential_en}/kernels/`,
`coulomb/kernels/{pair_bound,dq,e_hermite,jab}/`), whose
`.clang-format` turns formatting off, and
`devtools/check-int-types.py` skips a file by FelizJueves's first-line banner:
the files stay byte-for-byte as emitted, so a fix belongs in the generator.

**One class per unordered pair of momenta.** `mmd` swaps every shell pair into
`la <= lb`, so `(s|p)` has a kernel and `(p|s)` does not need one. The
matrices are symmetric and the kernels write each value at `(m, n)` and
`(n, m)`, so the swap changes nothing about the result.

## Tests

`test/gtest/mmd_gpu.cpp` (the records), `test/gtest/overlap_gpu.cpp` (S) and
`test/gtest/core_hamiltonian_gpu.cpp` (T, V and H), against libcint and PySCF's
`hcore` through the golden data in `test/gtest/data/one_electron/`, and
`test/gtest/coulomb_gpu.cpp` (J), against libcint's `vj` through
`test/gtest/data/coulomb/`.
