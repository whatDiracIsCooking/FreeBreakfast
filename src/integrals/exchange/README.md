# Exchange

The Cartesian exchange matrix `K_ab = Σ_cd D_cd (ac|bd)` of an AO density, by
McMurchie–Davidson, on the GPU, from kernels generated by
[FelizJueves](../../../deps/FelizJueves) (`Target.K`, `kernel_kblock.py`): one
warp per contracted shell block `K_ab`, opt-UM's mapping (Palethorpe, Stocks &
Barca, arXiv:2407.21445, §4.3). **Schwarz-screened** at `tau` (default
`1e-10`): a block's warp stops its bra loop at the first bra with
`Ip · Iq[ket0] · max|D| < tau`, and each lane its ket loop at its first ket
with `Ip · Iq · max|D| < tau`.

## Module

`free_breakfast.integrals.exchange`, also re-exported by
`free_breakfast.integrals`. It re-exports
[`free_breakfast.integrals.exchange.pairs`](pairs/README.md), so the one
import gives both the ordered classes the build reads and the build:

```cpp
auto mmd = primitive_pair_classes(res, basis);              // once per basis
auto classes = ordered_pair_classes(res, basis, *mmd);      // once per basis
FBF_TRY(exchange(res, *classes, density, k));               // per density
```

## Design

FelizJueves's `kb_driver` (`test/kblock_driver.py`) and `launch_kblock.py` are
the launch contract. K has no symmetry inside a pair, so its bra `(a, c)` and
ket `(b, d)` are **ordered** shell pairs, the first shell of each an output
index: every [ordered class](pairs/README.md) is both a bra class and a ket
class, and the generated `kb<la, lc, lb, ld>` (`kernels/kb/`, dispatched as
`kb_kernels[la][lc][lb][ld]`) is one per (bra class, ket class). Each record's
Schwarz bound is `mmd`'s `bound` field, formed once per basis; `kb` reads it
as `Ip` on the bra and `Iq` on the ket.

**One warp per `K_ab`.** A `kb` launch takes a **block table**: per block, a
range of bra records of one first shell `a` (every `(a, c)` record of the
class), a range of ket records of one first shell `b` (every `(b, d)`), and
the AO offsets of `a` and `b`. Every lane walks the block's bras, the lanes
take its kets, each lane keeps its own `K_ab` accumulator, and after one warp
reduction lane 0 adds the block into `K` itself. So there is no per-record
scratch and no scatter, and a launch's blocks never write the same element.
The ranges are the classes' groups as they are: each class is grouped by first
shell, the groups in basis order, each non-increasing in `bound`, which is the
order both of `kb`'s `break`s need. So the pairs' layout is the one
`kernel_k` used.

`exchange(res, classes, density, k)` runs:

1. On `res.stream()`: zero `K`, then `max|D|` (`exchange_density_max`,
   `helpers/`).
2. **The rank tables**, each class `(l, l)` on its own stream: the AO offset of
   every shell of momentum `l` by rank, read off its records' `rank_b` and
   `off_b` (`exchange_rank_offsets`). A class `(l, l)` names every shell of `l`,
   each paired with itself. The join closes the phase: every gather reads two
   tables. Then, for the symmetric sweep, on `res.stream()`, the first AO of
   every AO's shell, from the tables (`exchange_shell_starts`).
3. **The density blocks**, each class `(lc, ld)` on its own stream: `Dcd` of
   `(lc, ld)`, gathered from `D` (`exchange_gather_dcd`). Every `(lc, ld)` of
   two reached momenta is a reached class, so each `Dcd` has a stream. The join
   closes the phase: every bra class reads them.
4. **Every class as a bra**, each on its own stream: its `Ip` and its `Dcd`
   rows; then, for every ket class, its block table (`exchange_blocks`) and one
   `kb` launch over it into `K`, in that order.
5. For the symmetric sweep, after the join, on `res.stream()`: every `a > b`
   block of `K` set to its transpose (`exchange_mirror`).

**The block tables are made on the device**, per call, from the classes'
groups: each class carries its groups' bounds on the device (`group_start`),
and `exchange_blocks` writes one launch's table from a bra class's and a ket
class's, one thread block per bra group. The host knows the groups too, so it
counts each table's blocks itself (the grid and the allocation) and nothing is
read back: the build stays without a host synchronization. Made on the device
because the one screen that would drop whole blocks — opt-UM's linear-scaling
block screen, eq. 49, below — depends on the density, so a table that took it
could not be fixed per basis.

**The bra-ket swap.** `(ac|bd) = (bd|ac)`, so for a symmetric `D`,
`K_ba = K_ab^T`: only the shell blocks `a <= b` need computing. The symmetric
sweep's tables hold only those, cut on the device by AO offset (the groups are
in basis order, so offsets rise with them; the host's count compares shell
indices, the same order), and `exchange_mirror` then sets each element of an
`a > b` block from its transpose. An `a == b` block is computed whole and left
as it is. What is left of the duplication is inside the `a == b` blocks:
`O(n_shells)` of `O(n_shells^2)`. The paper's K does the same: it uses only
this symmetry (§4.3.1), and FelizJueves's `ao/k.py` "THE TWO SWEEPS" has the
identity and the unique-sweep reference.

**The precondition is a contract, not a check.** The symmetric sweep is only
`K` for a symmetric `D`, and `exchange` does not verify it: refusing would
cost a device pass over `D` *and* a host synchronization to read the verdict
back into the `Status`, where the build is otherwise fully asynchronous. So
`symmetric` (default `true`) is the switch: `false` launches every block and
mirrors nothing, `K_ab` and `K_ba` each computed directly, correct for any `D`
at twice the work. Handed a non-symmetric `D`, the symmetric sweep returns its
`K`'s `a <= b` blocks, mirrored.

What the kernels leave to the launcher, and how it is supplied:

| Input | Value | Why |
|---|---|---|
| bra fields | `p_*`, `zeta`, `pa_*`, `pb_*`, `s` of the bra class as `p_*`, `zeta_ac`, `pa_*`, `pc_*`, `s_ac` | "a" is a record's first shell, "b" (here `c`) its second |
| ket fields | the ket class's same fields as `q_*`, `eta`, `qb_*`, `qd_*`, `s_bd`, `Iq` = `bound`, `dd` = `rank_b` | the ket's first shell is `b`, its second `d` |
| `Ip`, `maxD` | `Ip = bound · max\|D\|` (`exchange_bra_bound`), `maxD = 1` | `kb` takes `maxD` by value, a host double, but `max\|D\|` is on the device, and reading it back would synchronize the host. The screen is the same product |
| `dc`, `dd` | `dc = rank_b · n_shells(ld)` per (bra class, `ld`) (`exchange_bra_rows`), `dd = rank_b` | the gather's `Dcd` row is `rank_c · n_shells(ld) + rank_d`; `dc` depends on the ket's `ld`, so a bra class has one row set per `ld` and none is stored |
| `n_dc` | `n_shells(lc) · n_shells(ld)` | an extent only, never read |
| `bra0` … `ko_b` | the block table, one segment of `n_blk` per field (`exchange_blocks`) | a block's bras and kets are one group each, so each range is non-increasing in `bound`: both screens are `break`s, and unsorted ranges would make them a wrong answer, not a slow one |
| `K`, `n_ao` | `K` itself, zeroed | lane 0 `atomicAdd`s the reduced block at `(ko_a, ko_b)`: no two blocks of a launch meet, and launches of several class pairs, from several streams, need no ordering |
| the launch | grid `n_blk`, block `kb_block_dim = {1, FJ_WAVEFRONT}`, **no dynamic shared memory** | `kb`'s `Ksh[(n_p + n_a n_b) · FJ_WAVEFRONT]` is static, sized for exactly that block |

**The shared-memory budget is checked at compile time.** `Ksh` is static, so
`exchange_launch.cu` `static_assert`s the formula
`(n_p + n_a n_b) · kb_block_dim[1] · 8` bytes, `n_p = (lp+1)(lp+2)(lp+3)/6`,
`lp = la + lc`, at the largest class, `(dd|dd)`, against 48 KiB: 71 slots,
18,176 B at 32 lanes and 36,352 B at 64. Beside it, the table's extents against
`kMaxAngularMomentum` and `kb_block_dim` against `kWarpSize`. The footprint is
`kernel_k`'s, unchanged.

The scratch (per bra class `n_rec` doubles of `Ip`, `(l_max + 1) n_rec`
`int32`s of `dc` and 6 `int32`s per block of its tables; one `Dcd` per class;
one rank table per momentum; `n_ao` `int32`s of shell starts; one double of
`max|D|`) is drawn from `res.device()`'s pool in `res.stream()`'s order and
returned in its order once every phase is joined back, so there is no host
synchronization. The shells' AO offsets and the shell counts by momentum are
read on the host off the classes' groups and their pinned `off_a`, which
`ordered_pair_classes` wrote before its copies.

**One text serves both warp widths.** `kb` is emitted `any_wavefront`: its
shuffles and its shared array read `FJ_WAVEFRONT`, which `deps/CMakeLists.txt`
sets from `WWR_WARP_SIZE`.

**Generated kernels are committed, not built.** `tools/emit_exchange_kernels.py`
writes `kernels/kb/` from the FelizJueves submodule; re-run it after bumping the
submodule. `kernels/.clang-format` turns formatting off, and
`devtools/check-int-types.py` skips a file by FelizJueves's banner, so the files
stay byte-for-byte as emitted: a fix belongs in the generator.

## Not done

- **The linear-scaling block screen** (arXiv:2407.21445 §4.3.1, eqs. 41–49):
  fit `|D_cd| <= H e^{-Λ|CD|}` per density, and skip a block before any
  integral when `H e^{-Λ(|AB| - R_a - R_b)} G_a G_b <= τ*`. The bra loop's
  `break` already skips a block whose first bra fails the Schwarz bound
  (`G_a G_b max|D| < tau`, with the sort); the decay fit would tighten that
  `max|D|`. FelizJueves left it as a launch filter, and `kb`'s parameters take
  any table. Here it would go in `exchange_blocks`, with the per-shell `G_a` and
  `R_a` (fixed per basis, reductions over a first-shell group) beside
  `group_start`. A block it drops cannot leave the grid without the host
  learning the count, so it would leave the block in with an empty bra range.
- **The swap inside the diagonal blocks.** An `a == b` block is computed
  whole, so its quartets are still visited twice: `O(n_shells)` blocks of
  `O(n_shells^2)`.
- **Batching.** One `kb` launch per (bra class, ket class), every block at
  once, as FelizJueves ships it; no split class.
- **Reuse across SCF iterations.** The scratch, the rank tables, the block
  tables and `Dcd` are allocated and rebuilt per call. Without the block
  screen the tables are fixed per basis.
- **Nothing is measured.** FelizJueves has not timed `kb` against `kernel_k`
  either (its `measure.sh kblock` run was refused by the card gate).

## Public API

| Symbol | Role |
|---|---|
| `exchange(res, classes, density, k, tau = 1e-10, symmetric = true)` | `Status`: the Cartesian K of `density` into `k`, from `ordered_pair_classes` of the same basis, screened at `tau` (`0` screens nothing), by the `a <= b` blocks mirrored (`symmetric`, which requires a symmetric `density`, unchecked) or every block directly. InvalidConfig for a negative or NaN `tau`, another device, a density of another order, a class above d, a shell past `k`'s order, `k.n()^2` past `INT32_MAX`, or a block table past `INT32_MAX` int32s |
| `OrderedPairClass`, `ordered_pair_classes`, ... | re-exported from [`pairs/`](pairs/README.md) |

## Tests

`test/gtest/exchange_gpu.cpp`: `K` of H₂O in STO-3G and cc-pVDZ against
libcint's `vk` of the same density at `1e-12 · max|K|`, through the golden data
in `test/gtest/data/exchange/`, both at `tau = 0` and at the default (each run
records its worst error, and how far the screen moved `K`); `K` symmetric to
the same bar; the symmetric sweep against the full one at both `tau`s, with
the share of the full sweep's (bra, ket) record pairs its blocks cover recorded
(0.58 in cc-pVDZ, 0.60 in STO-3G: the diagonal blocks weigh more in a small
basis, and the share falls toward a half as the shells grow in number); on a
non-symmetric density, the symmetric `K` equal to the full one's `a <= b`
blocks and their transposes, not its own `a > b` blocks, which shows those are
mirrored, never computed; a `tau` above every bound gives exactly zero, which shows the
screen reaches the kernel and fires; the zeroing; and the refusals. The
helpers, the block table, the shell starts and the mirror among them, are
`exchange_helpers_gpu.cpp`'s test, and the classes, their `group_start` among
them, `exchange_pairs_gpu.cpp`'s.
