# dq

The J build's ket pre-contraction on the GPU, over the `dq<lc, ld>` kernels
FelizJueves generates: per class, `D_q = w Σ_cd D_cd s E^cd_q` and
`Dmax = max_q |D_q|`, reading the AO density in place.

## Module

`free_breakfast.integrals.coulomb.dq`, driven by
`free_breakfast.integrals.coulomb`'s `coulomb`.

## Design

`dq(ket, density)` launches on the class's own stream: a one-thread-per-record
kernel writes each record's weight `w` (2 for two shells, 1 for a shell against
itself), then the generated kernel writes `D_q`, q-major, and `Dmax`, all into
the class's scratch in record order. The ket sort then reads them
([`../README.md`](../README.md) has the build, and why `D_q` is q-major).

It checks nothing: `coulomb` has checked the density and the classes first.

**The kernels.** `kernels/dq_{00,01,02,11,12,22}.cu` (every `lc <= ld <= 2`),
generated by `tools/emit_coulomb_kernels.py` and committed as emitted. Each is
one explicit specialization of the kernel template `dq`, compiled as a source
of the device library; `dq_launch.cu` includes only `kernels/dq.h` and
launches through its `dq_kernels` table.

**The family layout** is `../../one_electron/overlap/`'s; that parent README's
"One layout per kernel family" has the table.
