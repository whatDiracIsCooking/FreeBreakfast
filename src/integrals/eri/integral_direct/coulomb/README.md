# Coulomb

The Cartesian Coulomb matrix `J_µν = Σ_λσ (µν|λσ) D_λσ` of an AO density, by
McMurchie–Davidson, on the GPU, from kernels generated by
[FelizJueves](../../../../../deps/FelizJueves). **Schwarz-screened** at `tau`
(default `1e-10`): each ket class is sorted descending by its bound `Iq · Dmax`
([`sort_bounds/`](sort_bounds/README.md)), and `e_hermite` stops a lane at its
first ket under `tau`. Its records are its own `CoulombPairClass`es: a device
copy of `mmd`'s with the negligible primitive pairs **pruned**
(`coulomb_pair_classes`, once per basis, on the device), **which assumes
`|D_cd| <= 2`** (below); `tau = 0` there keeps every record.

## Module

`free_breakfast.integrals.eri.integral_direct.coulomb`, also re-exported by
`free_breakfast.integrals`. It re-exports
`free_breakfast.integrals.eri.integral_direct.coulomb.pair_class` (J's classes
and the prune), and drives the build's three steps, each a module of its own
over one generated kernel family:

```
pair_class/   free_breakfast.integrals.eri.integral_direct.coulomb.pair_class: CoulombPairClass, and coulomb_pair_classes, the prune that makes them
dq/           free_breakfast.integrals.eri.integral_direct.coulomb.dq: the ket pre-contraction, over dq<lc, ld>
e_hermite/    free_breakfast.integrals.eri.integral_direct.coulomb.e_hermite: the [p|q] contraction, over e_hermite<lp, lq>
j_coulomb/    free_breakfast.integrals.eri.integral_direct.coulomb.j_coulomb: the bra back-transform and scatter into J, over jab<la, lb>
sort_bounds/  free_breakfast::integrals::eri::integral_direct::coulomb::sort_bounds::device: the ket sort
```

## Design

FelizJueves's `docs/implementation/j_engine.md`, "The J chain as device code",
is the contract the kernels were built against. Every class of J's records
(`CoulombPairClass`, from `coulomb_pair_classes`) is both a ket class and a
bra class.
Each record's Schwarz bound `I = pair_bound(ζ, la + lb)`, `e_hermite`'s `Ip`
as a bra and `Iq` as a ket, is not formed here: it depends on ζ and `la + lb`
only, so it is `mmd`'s `bound` field, formed once per basis
([`../../../mmd/`](../../../mmd/README.md)) and carried into J's classes, and a build
reads it.

| Step | Template | One per | Computes |
|---|---|---|---|
| ket pre-contraction | `dq<lc, ld>` ([`dq/`](dq/README.md)) | ket pair class, `lc <= ld` | `D_q = w Σ_cd D_cd s E^cd_q` and `Dmax = max_q \|D_q\|`, reading the AO density in place |
| ket sort | `sort_bounds_kets` (not generated) | ket pair class | the class's records sorted descending by `Iq · Dmax`, and `zeta`, P, `Iq`, `Dmax` and `D_q` gathered into that order, the class's `ket_` fields |
| `[p\|q]` | `e_hermite<lp, lq>` ([`e_hermite/`](e_hermite/README.md)) | (bra class, ket class), `lp = la + lb`, `lq = lc + ld` | `J_p += Σ_q [p\|q] D_q`, one warp per bra record, kets strip-mined, `J_p` added atomically |
| bra transform + scatter | `jab<la, lb>` ([`j_coulomb/`](j_coulomb/README.md)) | bra pair class | `J_ab += Σ_p s E^ab_p J_p`, added atomically into `J_µν` at (m, n) and (n, m) |

`coulomb(res, classes, density, j)` runs them **ket-major**, as two phases
of `launch_each` (the one-electron builds' per-class launch, reused with their
pre-launch checks from `free_breakfast.integrals.one_electron.launch`):

1. On `res.stream()`: zero `J` and every class's `J_p`, and fill `row` below.
2. **Every class as a ket**, each on its own stream: its records' weights `w`,
   then `dq`, then the ket sort (keyed on the class's `bound` times `Dmax`),
   then `e_hermite` of every bra class against it, into that bra's `J_p`. A
   ket class's sorted copies are written and read on its own stream only, so
   each ket starts contracting as soon as its own sort is done. The bras'
   records are only read, and their `J_p` only added to, atomically, from
   every ket class's stream at once. The join closes the phase: a bra's `J_p`
   is complete only once every ket class has added to it.
3. **Every class as a bra**, each on its own stream: `jab` of its `J_p` into
   `J`. The bra side reads its class in record order, which `mmd` makes
   descending ζ, so descending `Ip`, once per basis and at no cost per build.
4. Every class's stream forked from `res.stream()` once more, succeeded or
   not: a ket's stream read every other class's records, so a class's own
   frees, queued on its stream later, must follow every class's stream.

What the kernels leave to the launcher, and how it is supplied:

| Input | Value | Why |
|---|---|---|
| `w` | 2 for a shell pair of two shells, 1 for a shell against itself (`off_a == off_b`, as `mmd` records it) | `mmd` stores each unique shell pair once; the sum over all `(c, d)` counts the others twice. A one-thread kernel in `dq/dq_launch.cu` writes it per build |
| `Ip`, `Iq` | the bra's `bound` field (`mmd`'s) in record order, the ket's sorted copy (`ket_bound`) | The screen is `Dmax · Ip · Iq < tau` |
| `tau` | `coulomb`'s, default `1e-10` | The screen `break`s on a lane's first ket under `tau`, which is right only for kets sorted descending by `Iq · Dmax`: so they are |
| `row` | the record index | `jab` reads record `k`'s row of `J_p`; with one batch per class that row is `k`. `j_coulomb_rows` fills it |
| `J`, `J_p` | zeroed | Both are only added to |
| the block | `e_hermite_block_dim`, `{1, FJ_WAVEFRONT}` | `e_hermite`'s shared `J_p` accumulator is sized for exactly that block |

**The scratch is the class's.** Per class, `n_rec × n_hermite(la + lb)`
doubles for `D_q`, as many for the sorted `D_q` and as many for `J_p`, plus
`2 n_rec` for `w` and `Dmax` and `10 n_rec` for the sort (its keys, its
permutation, each with an alternate, and the six sorted per-record arrays),
all `CoulombPairClass` fields, allocated with its records on its own stream
by `coulomb_pair_classes` ([`pair_class/`](pair_class/README.md)), once per
basis. That is O(records), the order of the
records themselves, and an SCF loop allocates nothing per build but the
`max(n_rec)`-long `row`, from `res.device()`'s pool in `res.stream()`'s order;
there is no host synchronization. The price is that a build writes its
classes: **one `coulomb` at a time per set of classes.** Builds queued on one
stream are ordered by their forks and joins, so an SCF loop is fine; two
builds over the same classes on two streams would race on the scratch.

**The swap needs nothing.** `mmd` stores a pair whose bra has the higher
momentum swapped; `dq` reads the symmetric density at the record's own offsets
(FelizJueves's `density="ao"`) and `jab` writes `J` and its mirror, so neither
orientation is ever transposed.

**One text serves both warp widths.** `e_hermite` is emitted `any_wavefront`:
its shuffles and its shared array read `FJ_WAVEFRONT`, which
`deps/CMakeLists.txt` sets from `WWR_WARP_SIZE`. `dq` and `jab`
have no shuffle. Record vectors are three flat arrays per axis, named as `mmd` names its
fields.

**`D_q` is q-major.** `dq` writes `D_q` as `D[n_hermite, n_rec]` and
`e_hermite` reads it so (FelizJueves's `passes.transpose` on both, applied by
the emitter): `e_hermite`'s lanes are consecutive kets, so a warp reads
`D[q * n_ket + k]` contiguously, where record-major put each lane `n_q`
doubles apart. EXESS's J engine transposes `D_q` for the same reason
(`[Fock]` §4.2). The ket gather keeps the layout, moving columns. `J_p`
stays record-major: each warp owns one bra's row.

**Generated kernels are committed, not built.** `tools/emit/coulomb_kernels.py`
writes each step's `kernels/` (`dq/kernels/`, `e_hermite/kernels/`,
`j_coulomb/kernels/`) from the FelizJueves submodule; re-run it after bumping
the submodule. Each `kernels/.clang-format` turns formatting off, and
`devtools/check-int-types.py` skips a file by FelizJueves's banner, so the files
stay byte-for-byte as emitted: a fix belongs in the generator.

**The screen at f.** The default `tau = 1e-10` is coarse for an f basis.
`tau` bounds each skipped term of a `J_p`, and `jab` weights those terms by the
bra's `E^ab_p`, which are large at f. On CO in cc-pVTZ (the golden's
Hilbert-matrix density, `max|J|` 18.4), the default screen moves `J` by
3.1e-11, or 1.7e-12 of `max|J|`, which is past the libcint bar. The worst error
against libcint at each `tau` (RTX 3080):

| `tau` | H₂O/cc-pVDZ | CO/cc-pVTZ | CO / `max\|J\|` |
|---|---|---|---|
| 1e-10 (default) | 5.9e-13 | 3.1e-11 | 1.7e-12 |
| 3e-11 | 6.0e-13 | 4.5e-12 | 2.5e-13 |
| 1e-11 | 6.0e-13 | 1.2e-12 | 6.6e-14 |
| 3e-12 | 9.3e-13 | 7.3e-13 | 4.0e-14 |
| 1e-12 | 5.4e-13 | 1.2e-13 | 6.8e-15 |

The default is unchanged: lowering it would change every caller's cost.

## Not done

- **Reuse across geometries.** The classes, scratch included, are remade per
  basis, so an AIMD step reallocates them; classes that grow to a high-water
  mark and refill in place would not.
- **Batching.** One `e_hermite` kernel per class, as FelizJueves ships it.
- **A checked cap.** `coulomb` does not check its density against
  `coulomb_pair_classes`' `|D_cd| <= 2`; the classes do not carry the
  threshold they were pruned at.
- **A dressed `Ip`.** Pruning drops the far bras once per basis; a bra screen
  on a dressed bound would drop them per density instead, which is a change to
  J's screen and its guarantee (#132 left J's screen out of scope).

## Public API

`CoulombPairClass` and `coulomb_pair_classes` are
[`pair_class/`](pair_class/README.md)'s, re-exported here; the steps' own
functions are in their READMEs.

| Symbol | Role |
|---|---|
| `coulomb(res, classes, density, j, tau = 1e-10)` | `Status`: the Cartesian J of `density` into `j` from J's `classes`, screened at `tau` (`0` screens nothing). Writes the classes' scratch, so one call at a time per set of classes. InvalidConfig for a negative or NaN `tau`, another device, a density of another order, a class above f, or `j.n()^2` past `INT32_MAX` |

## Tests

`test/gtest/coulomb_gpu.cpp`: `J` of H₂O in STO-3G and cc-pVDZ, and of CO in
cc-pVTZ (f on both atoms, every class through `(6, 6)`), from every record
(J's classes pruned at `0`) against libcint's `vj` of the same density at
`1e-12 · max|J|`, through the golden data in `test/gtest/data/coulomb/`, both
at `tau = 0` and screened (each run records its worst error, and how far the
screen moved `J`). H₂O is screened at the default; CO at `1e-11`, for the
reason "The screen at f" gives; a `tau` above every
bound gives exactly zero, which shows the screen reaches the kernel and fires;
the zeroing; and the refusals. `tau` bounds each skipped term of a `J_p`, not
the error in `J`, so the screened bar is the same measured `1e-12`, not one
derived from `tau`. The pruned records' tests are
[`pair_class/`](pair_class/README.md)'s. The bound the screen reads is `mmd`'s, and
`mmd_gpu.cpp`'s test. The sort itself is
[`sort_bounds/`](sort_bounds/README.md)'s test. Every J test builds ket-major,
so the goldens also exercise every ket class's stream adding into each bra's
`J_p` before `jab` reads it.
