# j_coulomb

The J build's bra back-transform on the GPU, over the `jab<la, lb>` kernels
FelizJueves generates: `J_ab += Σ_p s E^ab_p J_p`, one bra class's `J_p`
scattered into the Coulomb matrix J.

## Module

`free_breakfast.integrals.eri.integral_direct.coulomb.j_coulomb`, driven by
`free_breakfast.integrals.eri.integral_direct.coulomb`'s `coulomb`.

## Design

`j_coulomb(bra, rows, j)` launches the generated kernel on the bra class's own
stream, one thread per record, each adding its values at `(m, n)` and `(n, m)`
with fp64 atomics, so J must be zeroed first and is symmetric after the last
class. The class's `J_p` must be complete: every ket class's `e_hermite` has
added to it. `rows` is the kernels' record-to-row map of `J_p`, the identity
with one batch per class; `j_coulomb_rows` fills it.
[`../README.md`](../README.md) has the build.

It checks nothing: `coulomb` has checked J and the classes first.

**The kernels.** `kernels/jab_{la}{lb}.cu`, every `la <= lb <= 3`
(`kCoulombMaxMomentum`, f), generated by `tools/emit_coulomb_kernels.py` and committed as emitted. Each is
one explicit specialization of the kernel template `jab`, compiled as a source
of the device library; `j_coulomb_launch.cu` includes only `kernels/jab.h` and
launches through its `jab_kernels` table. The kernels keep FelizJueves's name,
`jab`; the module is named for what it builds. `jab_33` is FelizJueves's
low-stack text (`kernel_jab.jab_lowstack`, `la + lb >= 6`: 2,688 B of stack a
thread, no spill, where the unrolled one took 71 KB); every other class is
unrolled.

**The family layout** is `../../../../one_electron/overlap/`'s; that parent README's
"One layout per kernel family" has the table.

## Public API

| Symbol | Role |
|---|---|
| `j_coulomb_rows(stream, rows)` | `wwrError_t`: `rows[k] = k`, on `stream` |
| `j_coulomb(bra, rows, j)` | `wwrError_t`: the bra class's `jp` added into `j`, on its stream |
